# 擎天樹支架：七輪自行比對與修正

以使用者提供的圖片為主要視覺參考。每輪都重新產生 Geometry Nodes 模型，渲染支架拆解圖與原相機構圖，再對照放大的左緣、右緣和頂端。

## 這次比對看到的重點

參考圖的外冠以長桿為主，短桿在不同半徑錯位分出 L、T、Y 形接法。部分短桿接回長桿，形成局部開口或長形框格；整體並非規則蜂巢，也不是一圈圈完整圓環。桿件粗細足以在整張畫面中讀出，末端有明確的折角。

## 逐輪結果

| 輪次 | 實際修改 | 對照後的判斷 |
|---|---|---|
| 0／開始前 | 單層 Y 分叉與少量短連桿 | 外緣過於單薄，中段缺少參考圖的錯位構造。 |
| 1 | 連續的規則六邊形格網 | 否決：像蜂巢網，沒有長主桿和短折枝的層級。 |
| 2 | 把格網轉向並拉長，增加徑向直桿 | 否決：仍然是封閉而規則的網格，與放大的參考局部不符。 |
| 3 | 改成開口的 L／Y 短枝，分布在三個不同半徑 | 採用這個方向；但主桿的彎折與漸細太像自然樹枝。 |
| 4 | 主桿徑向拉直，外段改用一致的箱形截面 | 鋼架感較好；完整畫面對照仍顯得長桿偏少。 |
| 5 | 每組主肋分成兩支長桿，重新分配短枝；枝端總數仍是 128 | 採用：32 組主肋 → 64 支長桿，並配 64 組短側枝。 |
| 6 | 加粗實際桿件截面，降低深色塗層的天空反射 | 採用：短折枝在整張構圖中的可讀性改善，沒有增加分枝數量。 |
| 7 | 每組模組增加兩根局部短連桿，接到明確分割的長桿節點 | 最終採用：補上參考圖的錯位連接，但不形成完整外冠圓環。 |

每輪的 `build.py`、`piece.blend`、`preview.png`、`structure.png`、`structure-bay.png` 均保留在對應的 `roundNN-*` 資料夾。

## 最終模型

- 32 組彎曲主肋，在冠緣分成 64 支長桿。
- 64 組 L／Y 短側枝，128 個開放枝端。
- 64 根局部短連桿，兩種鏡像模組錯位排列。
- 箱形截面、主次桿粗細分明；光面上的黑色條紋改由真正的支架幾何形成。
- 保留弧形發光內冠和分層深色頂蓋。

## 檢查

`../../checks/verification.json` 記錄最終主樹的中心線圖與幾何檢查：

- 1,984 個頂點、2,048 條邊，為一個連通分量。
- 128 個末端、256 個三向接點，沒有額外未接上的構件。
- 對外冠非相鄰桿件使用箱形截面的保守包圍半徑檢查，排除相接節點附近後，未發現意外穿插。
- 發光面仍通過弧面與網格連接檢查；程序化檢查也通過。

最小遠景樹另外以相同方式檢查。加粗截面後曾出現 16 組保守間距檢查警示；截面現在隨冠幅與主肋密度縮放，主樹保持原尺寸，最小遠景樹也已通過。結果記錄在 `../../checks/verification-smallest.json`。

這些是視覺模型的拓撲與穿插檢查，不是建築荷載驗算。參考照片與模型相機不同，對照圖僅依冠幅約略縮放，沒有扭曲參考圖來配合模型。
